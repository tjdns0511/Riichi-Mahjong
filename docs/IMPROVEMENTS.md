# 전략·후리텐·모바일·패효율 개선 (2026-10-08)

기준 main: `1f5bee656b22d9dd3efd0e1f4ef29fe827da5632`. 기존 Vanilla ES 모듈, MIT, 대국·저장·리플레이·학습 도구를 유지했다.

## 원인과 수정

기존 고급 AI는 위협을 만나면 위험 지수 가중치가 샨텐·타점보다 지나치게 커서 유리한 텐파이도 쉽게 포기했다. 타패 평가에 후리텐과 실제 역 성립 구분이 없고, 안전해 보이는 상황의 깡은 거의 자동이었다.

현재 평가는 후보를 버린 후의 샨텐·유효패, 대기 전체의 후리텐, 점수 엔진이 확인한 론/쯔모별 역, 미확인 매수, 도라·적패·멘젠 가치, 상대별 위험, 친·순목·패산 길이·오라스 점수 차이를 결합한다. 좋은 텐파이는 공격할 수 있고, 저타점/늦은/먼 손패는 안전도 비중을 높인다. 역 없는 구조적 텐파이는 화료에 추가 진행이 필요하므로 정상 텐파이보다 높은 비용을 부여한다. 수비상 합법적인 후리텐/역 포기 타패는 강제 금지하지 않는다.

치·퐁은 엔진이 제공한 쿠이카에 제한 안에서 울기 후 최적 타패를 비교한다. 텐파이는 실제 역을 검사하고, 노텐은 역패·탕야오·혼일색·청일색·찬타·삼색의 노출 몸통 호환성과 부족 패를 검토한다. 노텐 역 경로는 제한적인 휴리스틱이며 완전 탐색은 아니다. 안깡·가깡·밍깡은 엔진의 합법 옵션만 사용하고 샨텐/대기 변화, 영상패 기회, 남은 패산과 상대 위협 및 신도라 불확실성을 비교한다. 중급은 멘젠과 효율·기본 화료 가능성, 초급은 단순 효율과 시드 기반 일부 쯔모기리로 구분한다.

`evaluateDiscards/evaluateCalls/evaluateKan`은 판단의 구성 요소를 반환한다. 화면의 **추천 타패 보기 → 고급 AI의 판단 근거**에서 후보별 공격·수비, 론/쯔모 매수, 타점 평가와 상대별 위험 이유를 볼 수 있다. 위험 지수·비교 비용은 확률 또는 엄밀한 기대값이 아니다.

기존 탁자는 절대 좌표에 버림패를 고정해 새 줄의 공간을 확보하지 못했다. 이제 점수/후로와 버림패를 같은 독립 영역 안에 두고 Grid가 내용 높이를 확보한다. PC는 동서남북 배치, 좁은 화면은 정보 행 아래 2열 배치다. 6장씩 행을 만들고 회전한 리치패의 가로 길이도 예약한다. 숨김/레이어 겹치기로 해결하지 않았다. 손패는 터치 크기를 유지하며 줄바꿈하고 경고는 손패·버튼 아래 문서 흐름에 배치한다.

연습은 선택 즉시 실제 타패를 반영한 13장에서 텐파이를 판정한다. 일반형·치또이츠·국사 모두 즉시 종료하며 추가 쯔모/중복 입력을 무시한다. 기록에는 당시 14장과 공개 매수, 선택/모든 최적 후보, 샨텐·유효패·손실·이유가 남는다. 미래 쯔모를 참조하지 않는다. 점수는 기존대로 **최소 샨텐을 유지한 타패의 유효패 수**, 분모는 **각 순 최적 유효패 수 합계(0장이면 1점)**다. 최종 13장·대기별 형태/미확인 매수·총 타패 수·점수/비율·개선 선택·순별 전체 비교와 재시작/메뉴 이동을 제공한다.

후리텐은 엔진에서 UI로 복제하지 않고 공통 모듈로 이동했다. 선택한 물리 패를 가상 제거하고 이번 버림패를 포함한 대기 전체를 검사한다. 현재 후리텐의 유지/신규 발생/해제를 구분하고, 복수 원인 패를 이미지와 자기 버림패 강조로 표시한다. 6삭이 원인이면 9삭도 론 금지다. 쯔모는 점수 엔진으로 역을 별도 검사하며 0장 대기는 흐린 패/점선/미확인 0장으로 구별한다. 미래 우라·잇파츠·해저·영상은 미리 가정하지 않는다. 선택 변경/취소와 두 번째 탭 타패를 지원하며 미리보기는 실제 상태를 바꾸지 않는다.

## 검증 및 비교

74개 단위/회귀 테스트가 [Actions 실행 37707182367](https://github.com/tjdns0511/Riichi-Mahjong/actions/runs/37707182367)에서 통과했다. 기존 47개 테스트에는 24개 고정 시드 대국의 물리 패/점수 보존 및 정확한 JSON 재생이 포함된다. 추가 테스트는 전체 후리텐, 자기 타패 원인, 복수 원인/0장 대기, 일시 해제/영구 상태/쯔모, 순수 미리보기, 세 형태 연습 종료, 중복 입력·점수/이력, 역 없는 울기·노텐 복귀·합법/비합법 깡, 고급 공격/수비 및 결정론을 검사한다. Proxy가 타가 손패·미래 패산·미공개 표시패/우라 접근 시 예외를 던지는 테스트도 통과했다.

고급 AI의 유리한 텐파이 회귀 상태에서 기존 정책은 현물을 버려 1샨텐으로 되돌아갔고, 새 정책은 0샨텐을 유지했다. 이는 해당 행동의 개선 확인이며 전체 승률 증명은 아니다.

AI 비교는 시드 8개 전부를 사용했다. 기존 4명끼리의 8반장과 새 AI 한 명을 각 좌석에 배치한 32반장, 총 40반장이다. 상대 3명은 동결한 기존 Hard다. 각각 32개 좌석 관측으로 비교했으며 같은 시드의 관측은 독립이 아니다. 이 시드는 개발 중 오류 진단에도 사용했으므로 독립된 검증 표본이 아니다.

- 평균 순위: 기존 **2.5000** → 새 AI **2.3125**.
- 평균 획득 점수: **0** → **+2,150점**.
- 화료율(관측 좌석이 참여한 국): **49/336 = 14.58%** → **68/354 = 19.21%**.
- 방총률(같은 분모): **16/336 = 4.76%** → **36/354 = 10.17%**.
- 후리텐 텐파이 타패(강제 리치 타패 포함): **9/666 = 1.35%** → **20/897 = 2.23%**.
- 역 없는 텐파이 타패: **4/666 = 0.60%** → **0/897 = 0%**.
- 실제 치·퐁·밍깡: **69 → 92회**, 즉시 샨텐을 줄이지 않은 호출 **0 → 0회**.
- 실제 깡(밍깡 포함): **9 → 3회**, 12장 미만 패산/공개 위협 중 깡 **0 → 0회**.

점수·화료와 함께 방총·후리텐 빈도도 증가했다. 후리텐을 금지하지 않으므로 빈도 감소 자체를 목적함수로 삼지 않았다. **통계적으로 더 강해졌다고 단정하지 않는다.** “불필요한 울기/깡”은 최적 전략을 알지 못하므로 증명할 수 없고, 위의 샨텐/위협 지표는 진단용 대리 지표다. 노텐 역 경로와 공격·수비 계수의 추가 검증 여지가 남아 있다.

원자료 및 화면은 실행의 `browser-screenshots` 아티팩트에 포함된다(7일 보관). 요약은 [ai-benchmark-summary.json](ai-benchmark-summary.json)에 보존했고 `node tests/ai-benchmark.mjs`로 재현할 수 있다.

## 브라우저와 모바일

Chromium에서 320×568, 360×800, 393×873, 412×915, 768×1024, 1440×1050, 873×393 및 각 화면의 가로/세로 전환을 검사했다. 각 크기에서 네 플레이어 모두 6·12·18·24·30장을 놓았다. 이 중 극단 상태는 레이아웃 스트레스용 합성 데이터이며 정상 대국 패산 상태라는 뜻은 아니다.

버림패끼리, 점수/후로, 중앙 정보, 도라, 손패/경고/버튼의 실제 DOM 사각형을 검사하고, 회전 리치패가 확보된 영역 밖으로 나가거나 다른 패와 교차하지 않는지 확인했다. 393px와 PC 대국/후리텐 화면, 393px 결과 화면의 실제 캡처도 검토했다. 기존 화면 흐름과 새 연습 완주/재시작은 별도로 실제 앱 이벤트로 검사했다.

CI 실행 당시 고급 AI 40손패 데스크톱 p95 **5.6ms**, 최대 **7.2ms**. Chromium CPU 4배 감속에서 p95 **13.3ms**, 최대 **29.4ms**. 실행마다 수치는 달라지며 실제 A34 측정이 아니다. **실물 Galaxy와 삼성 인터넷, 다른 브라우저 엔진은 미검증**이다. 앱 런타임에는 Playwright나 Node가 들어가지 않는다.

## 배포 안전성

정적 ES 모듈과 상대 경로를 유지해 GitHub Pages 하위 경로에서 실행한다. 서비스 워커 캐시는 새 모듈 그래프와 함께 갱신한다. 진행 중 대국/패보 v1의 엔진 동작과 명령 재생 형식은 보존한다. 작업 브랜치는 테스트만 실행하고, main의 테스트가 모두 성공한 경우에만 배포한다.

배포 후에는 공개된 index/CSS/서비스 워커/app/AI/공통 판정/연습/후리텐 UI 파일 8개의 SHA-256을 체크아웃과 대조해 CDN에 같은 코드가 올라왔는지 검사한다.
