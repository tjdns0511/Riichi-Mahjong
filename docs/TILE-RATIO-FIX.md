# 패효율 손패 비율 수정 — 2026-10-08

기준 main은 `93be9279825656151d8697ca695f119c5010f88d`다. 런타임 소스를 수정하기 전에 측정 코드만 추가한 [실행 37720374734](https://github.com/tjdns0511/Riichi-Mahjong/actions/runs/37720374734)에서 문제를 재현했다. 수정 후 [실행 37720856916](https://github.com/tjdns0511/Riichi-Mahjong/actions/runs/37720856916)에서 검증했다. 전체 수치는 [efficiency-hand-measurements.json](efficiency-hand-measurements.json)에 보존한다.

## 실제 원인과 가설 검증

진행 중 DOM은 `.practice-hand > .tiles-hand.hand > button.tile`이었다. 결과 손패는 `.efficiency-result > .tiles-hand.hand`, 순별 기록은 `.tiles-hand.history-hand`를 사용했다. JS는 크기를 설정하지 않았고 패 요소의 인라인 스타일도 없었다.

가변 너비와 고정 높이의 충돌이라는 가설은 맞았다. 다만 실제 적용 구간은 **1100px 이하가 아니라 700px 이하**다. 더 구체적인 `.practice-hand .hand`의 너비가 `.tiles-hand`의 36px보다 우선했고, 높이는 파일 아래쪽 `.tiles-hand`의 50px이 기존 비례식을 덮어썼다. `--tile-w`와 `--tile-h`, 실제 width/height와 flex-basis까지 서로 다른 출처를 사용했다.

- 320px: 너비 17.34375px, 높이 50px, 비율 2.88288, **2줄**.
- 360px: 너비 20.203125px, 높이 50px, 비율 2.47486, **2줄**.
- 390px: 너비 21.34375px, 높이 50px, 비율 2.34261, 1줄.
- 700px: 너비 43.5px, 높이 50px로 오히려 납작해졌다.
- 701px 이상에서는 고정 높이가 적용되지 않아 기존 1.38 비율이 대체로 맞았다.

줄바꿈에는 별도 원인이 있었다. 380px 이하의 `calc((100vw - 77px) / 14)`는 14장 너비와 13개 간격을 합하면 실제 컨테이너보다 4px 컸다. 예를 들어 320px에서 사용 공간은 약 282px, 컨테이너는 278px였다. 공통 `flex-wrap: wrap`이 이 초과분을 두 번째 줄로 보냈다. 따라서 높이만 고쳐서는 한 줄 배치까지 해결되지 않는다.

실측한 패는 border-box, 테두리 1px, padding 0, flex-shrink 0, min-width/min-height auto, max-width/max-height none, aspect-ratio auto였다. 최소·최대 크기나 JS 확대가 원인은 아니었다. 외부 SVG는 300×400 비율이며, 기존 `object-fit: fill`은 이미지까지 박스에 맞춰 늘릴 수 있었다.

## 선택한 방법

공통 50px을 비례식으로 바꾸는 방법은 대국·복기·계산기까지 영향을 준다. 패효율에 높이만 다시 덮어쓰는 방법은 기존 폭 계산과 줄바꿈 충돌을 남긴다. 그래서 **패효율만 `.efficiency-hand`로 분리**했다. `.tiles-hand`는 대국 등 기존 화면에 그대로 남겼다.

패효율 행은 container-type을 가진 한 줄 Flex다. 패 너비는 `min(53px, (컨테이너 내용 너비 - 13개 간격 - 쯔모패 간격) / 14)`로 계산한다. 패딩과 사이드바는 이미 내용 너비에서 제외되며, `height = width × 1.38`과 같은 flex-basis를 사용한다. 13장 상태에도 같은 14장 기준 크기를 유지해 타패 직후 크기가 흔들리지 않는다.

규칙은 기존 학습 화면 CSS 구간에 배치했다. 파일 끝에 우선순위 덮어쓰기를 추가하지 않았다. 진행 중·최종·기록 손패는 같은 렌더러를 사용한다. 이미지에는 패효율 범위에서만 `object-fit: contain`을 적용했다. 버림패·대기 카드·분석 표의 작은 패와 다른 화면은 기존 규칙을 유지한다.

기존 연습에는 쯔모패 표시가 없었다. 실제 물리 패 ID를 `drawn`으로 보관하고, 렌더링에서만 오른쪽으로 분리한다. 타패 후 해제하고 다음 쯔모/과거 이력에 맞게 갱신한다. 패산 순서, 손패 모델 정렬, 샨텐·점수 계산은 변경하지 않았다. 연습의 기존 한 번 탭 즉시 타패 방식도 유지한다.

## 검증 결과

76개 단위/회귀 테스트를 통과했다. Chromium에서 너비 320, 360, 390, 430, 700, 701, 768, 1024, 1100, 1440px 및 가로/세로 전환을 검사했다. 모든 손패의 실측 비율 오차는 0.002 미만이며 14장이 한 줄에 들어갔다. 타패 후 13장, 다음 쯔모, 터치, SVG 성공/실패 경로, 일반형·치또이츠·국사의 종료/최종 손패/순별 이력/재시작을 검사했다.

대표 수정 후 수치는 320px에서 **16.84375×23.25px**, 390px에서 **21.28125×29.359375px**, 768px에서 **32.0625×44.25px**, 1440px에서 **53×73.125px**다. 실제 border-box를 측정했으며 미세한 차이는 소수점 픽셀 반올림이다.

기존 여섯 탭, 핫시트, 두 번 탭/선택 취소, Worker, 패보 입출력/복기 검사도 통과했다. 별도 대국 스트레스 테스트는 320×568, 360×800, 393×873, 412×915, 768×1024, 1440×1050, 873×393에서 네 플레이어 버림패 1~5줄, 후로/깡, 리치패 회전, 후리텐 경고, 중앙 정보와 손패의 DOM 충돌 및 화면 초과를 검사했다.

## 검증 한계

실물 Galaxy와 삼성 인터넷은 직접 시험하지 않았다. 320px에 14장을 한 줄로 배치하면 패 너비는 약 17px이므로 대국 손패처럼 36px의 큰 터치 영역과 동시에 만족시킬 수 없다. 요청한 한 줄과 비율을 우선했으며 각 패의 터치 동작을 자동 검사했다. 이미지 성공 경로는 원본과 같은 300:400 비율의 테스트 SVG로 검사해 외부 서버 상태와 분리했다. 다른 브라우저 엔진 및 오래된 container query 미지원 브라우저는 미검증이다.
