# 모든 패의 공통 크기 규칙 — 1.1.4

## 원인

1.1.3까지 수비 손패는 `.practice-hand .hand.tiles-hand`였다. 700px 이하에서 `.practice-hand .hand`의 가변 너비가 적용되지만, 뒤쪽 `.tiles-hand` 규칙의 `--hand-tile-h: 50px`과 직접 `height` 지정이 높이를 고정했다. 패효율은 이전에 전용 행으로 분리했으므로 그 수정만으로 수비·계산기·복기까지 해결되지는 않았다.

기본 패·작은 패·뒷면·도라·후로에도 고정 너비/높이 쌍이 있었고, 버림패는 1.36, 계산기 팔레트는 1.4 비율을 사용했다. 높이가 여러 곳에 분산된 것이 같은 문제가 다른 화면에서 재발한 원인이다. JavaScript와 인라인 스타일은 패 크기를 설정하지 않는다.

## 공통 계약

`styles.css`의 `.tile` 한 곳에서 `width: var(--tile-w)`와 `height: calc(var(--tile-w) * var(--tile-ratio))`를 적용한다. 루트의 비율은 **1.38**, 두 크기는 테두리를 포함한 border-box다. 화면별 규칙은 **너비 변수만** 설정한다. 별도의 `--tile-h`, `--hand-tile-h`와 직접 높이 덮어쓰기는 제거했다.

높이를 조상 요소에서 계산해 상속하지 않고 실제 패에서 계산하므로, 더 구체적인 선택자나 화면 회전으로 너비가 바뀌어도 같은 패의 최종 너비를 사용한다. 예를 들어 20px이면 27.6px, 36px이면 49.68px다. 실제 브라우저에는 소수점 픽셀 반올림이 있다.

화면별 너비·간격·줄바꿈 정책, 패효율의 컨테이너 기준 14장 한 줄 계산은 유지한다. 리치 선언패는 그대로 90도 회전하며, 버림패 행 높이와 옆으로 누운 패의 자리도 같은 비율로 예약한다. SVG는 전체 화면에서 `object-fit: contain`으로 표시해 원본 그림을 늘리지 않는다. 유니코드 폴백은 유지한다.

너비를 고정해 높이 50px에 맞추거나 화면별 예외를 추가하는 방법 대신 공통 규칙을 선택했다. 수비만 고치면 다른 크기 조합에서 재발하고, 너비를 통일하면 기존 반응형 배치를 바꾸기 때문이다. 게임 규칙, 기록·내보내기, AI와 점수 계산은 변경하지 않았다.

## 회귀 검증

- `tests/browser-tile-ratios.mjs`: 모든 표시된 패의 computed style과 실제 사각형을 함께 검사한다. 회전패는 가로·세로를 되돌려 비교한다. 8px 뒷면의 소수점 반올림까지 고려한 허용 오차는 높이 0.035px다.
- 수비: 320, 360, 390, 430, 700, 701, 768, 1024, 1100, 1440px에서 손패, 선택·피드백, 상대 1/2명, 다음 문제, 가로/세로 전환을 검사하고 대표 실측값을 CI 로그에 남긴다.
- 대국·복기·계산기·패효율: 기존 브라우저 통합 경로에 공통 비율 검사를 추가했다. 손패·뒷면·도라·후로·분석 후보·대기·결과·순별 기록에 적용한다.
- 기존 네 방향 버림패 1~5줄, 치·퐁·깡, 리치 회전, 후리텐 경고의 DOM 충돌 검사를 그대로 유지한다. 패효율의 13/14장, 타패·쯔모, 세 형태 텐파이 종료, SVG 성공/실패 테스트도 유지한다.

실물 Galaxy와 삼성 인터넷의 검증은 Chromium 터치·뷰포트 에뮬레이션과 다르다. 작은 화면의 연습 손패 너비 정책은 기존 그대로이며, 전체 패 비율 통일이 터치 대상을 모두 같은 크기로 만든다는 의미는 아니다. 실행 결과는 해당 커밋의 GitHub Actions 로그와 `browser-screenshots` 아티팩트에서 확인할 수 있다.
