# 패효율 연습 기록 내보내기 v2

**패효율 → 기록 내보내기**에서 진행 중·종료 후 보고서를 확인합니다. 복사, 텍스트(.txt), Markdown(.md)는 동일한 UTF-8 본문을 사용합니다. 클립보드가 차단되면 본문을 직접 선택해 복사하거나 파일로 저장할 수 있습니다.

파일명에는 UTC 내보낸 시각이 들어갑니다. 본문 첫 줄의 형식 식별자는 `riichi-efficiency-report v2`입니다. 본문에는 시각을 반복하지 않아 동일한 상태는 항상 동일한 문서가 됩니다. 외부 분석용 내보내기이며 앱의 불러오기 기능은 추가하지 않았습니다.

## 분석 결과와 설계 선택

v1은 순마다 타패 전후 손패, 알려진 34종 매수, 모든 후보와 그 후보의 유효패 목록을 반복했습니다. 하지만 이 정보는 최초 손패와 쯔모·타패 이력에서 복원할 수 있습니다. 최초 14장과 첫 쯔모를 함께 출력해 첫 쯔모를 중복 적용할 여지도 있었습니다.

현 모델에는 첫 14장과 첫 쯔모의 물리 ID가 모두 있습니다. 첫 기록의 손패에서 해당 ID 한 장만 빼면 실제 시작 13장이 나옵니다. 첫 타패 전에는 현재 손패와 현재 쯔모 ID로 같은 처리를 합니다. 적5와 일반5가 섞여 있어도 정확한 한 장을 제거합니다. 쯔모 정보가 없으면 임의로 추측하지 않고 오류를 알립니다. 기록 모델과 게임 엔진의 수정은 필요하지 않았습니다.

시작 14장을 유지하고 첫 행만 예외로 해석하는 방식보다, 시작 13장과 모든 행에 동일한 쯔모→타패 규칙을 적용하는 쪽이 재현에 유리합니다. 각 행은 다음 여섯 열만 가집니다.

`순 | 쯔모 | 타패 | 샨텐(선택/최적) | 유효패(선택/최적) | 최적 타패`

샨텐 열은 반드시 필요합니다. 실제 시드 161의 첫 손패 `3445699m239p248s4z`에서 5만 타패는 3샨텐·19장, 최적 후보는 2샨텐·19장입니다. `19/19`만 보면 동률처럼 보이지만 전자는 0점입니다. 원래 엔진과 똑같이 최소 샨텐을 먼저 비교하고, 같은 샨텐에서 최대 유효패인 후보를 모두 표시합니다.

아직 타패하지 않은 쯔모는 완료한 행 뒤에 `미타패 쯔모(N순): 패`로 별도 출력합니다. 이를 생략하면 14장 상태의 내보내기가 재현되지 않고, 빈 타패 행으로 넣으면 완료한 순의 수와 혼동할 수 있습니다.

## 읽기·재현 방법

1. `시작 손패(13장)`를 읽습니다.
2. 각 행의 쯔모를 한 장 추가해 14장을 만들고, 실제 타패 한 장을 제거해 13장을 만듭니다.
3. 미타패 쯔모가 있으면 모든 완료 행 이후 그 패만 한 번 더 추가합니다. 그러면 현재 손패는 14장입니다.
4. 복원한 손패를 현재/최종 손패와 비교합니다.

동일한 일반 패끼리의 내부 물리 ID는 분석상 구별할 필요가 없습니다. 패의 종류·중복 장수·적패 여부는 모두 보존합니다. 쯔모와 타패가 같은 기호인 행도 실제로는 다른 일반 복사본을 버렸을 수 있으므로, 이 문서는 그 정보만으로 테다시/쯔모기리를 판정하지 않습니다.

쯔모·타패·손패의 `0m/0p/0s`는 적5입니다. 최적 후보는 엔진이 비교한 **종류**이므로 `5m/5p/5s`가 적5도 포함합니다. `z`의 1~7은 동·남·서·북·백·발·중입니다.

## 계산과 요약

- 각 행의 샨텐·유효패는 해당 타패 **후** 값입니다. 일반형·치또이츠·국사 중 최소 샨텐을 사용합니다.
- 후보별 미확인 장수는 `4 − (후보 타패 후 손패 + 해당 타패까지의 누적 버림패)의 장수`입니다. 타패 전 14장에 이번 타패를 또 더해 이중 집계하지 않습니다. 미래 쯔모를 포함하지 않습니다.
- 순별 획득 점수는 선택·최적 샨텐이 같으면 선택 유효패 수, 다르면 0입니다. 최대 점수는 각 순 `max(최적 유효패, 1)`의 합입니다. 실제 진행 경로의 분모이며 모든 가능한 경로의 전역 최대 점수가 아닙니다.
- 완료한 타패만 순목 수와 최적 선택 횟수에 포함합니다. 타패 전 0순에서는 0/0점으로 표시합니다.
- 상태는 텐파이, 패산 소진, 진행 중(타패 대기), 진행 중(쯔모 대기)을 구분합니다. 현재 손패를 종료 손패로 표시하지 않습니다.
- 텐파이일 때만 구조적 대기와 미확인 장수를 출력하며, 0장인 대기도 유지합니다. 대기는 역·후리텐까지 적용한 론/쯔모 허가가 아닙니다.

매 순의 모든 후보 목록·유효패 종류별 매수·손패·누적 점수·평가 문장은 출력하지 않습니다. 위 원본 이력으로 당시 공개 정보를 복원하여 다시 계산할 수 있습니다. 앱의 선택/최적 값은 그대로 유지해 외부 계산과 비교할 수 있습니다. 화면의 상세 분석과 두 번 쯔모 분석은 기존대로 사용할 수 있습니다.

## 실제 예시와 검증

[example-efficiency-report-v2.txt](example-efficiency-report-v2.txt)는 `newEfficiency(2)`에서 매 순 최적 후보를 선택한 실제 6순 기록입니다. 예시용 수치나 후보를 하드코딩하지 않고 기존 엔진과 새 내보내기로 생성했습니다.

같은 기록을 v1과 v2로 출력해 비교했습니다. 시드 2의 6순은 10,337→717자(93.1% 감소), 시드 3의 16순은 31,954→1,064자(96.7% 감소), 시드 1의 21순은 28,926→1,318자(95.4% 감소)였습니다. 이 비율은 해당 표본의 문자 수 기준이며 모든 기록에 대한 보장은 아닙니다.

`tests/efficiency-report-replay.mjs`는 테스트 전용 외부 리더입니다. 출력 문자열만 읽어 별도의 표기 해석·패 배분으로 진행을 복원한 뒤, 변경하지 않은 샨텐 엔진으로 평가를 다시 계산합니다. 앱에는 포함되지 않으며 불러오기 기능도 제공하지 않습니다.

`tests/efficiency-report.test.js`는 모든 중간 14/13장 손패, 적5/일반5, 중복 패, 미타패 쯔모, 세 종류 텐파이, 0장 대기·분모 1점, 공동 최적 후보, 샨텐 차이를 검증합니다. 고정 시드 24개의 혼합 선택 기록은 각 순 당시 손패·확인 매수·모든 후보까지 원래 기록과 비교합니다. 123순 패산 소진 기록으로 순당 한 행과 일정한 열 수도 검사합니다.

브라우저 통합 테스트는 화면의 손패·점수와 내보내기에서 재현한 값을 비교하고, 두 다운로드 파일·복사·클립보드 차단 대응·모바일 경계를 검사합니다. 실제 Galaxy 기기와 삼성 인터넷에서의 OS 파일 저장 창은 Chromium 에뮬레이션과 별도 검증 대상입니다.

v1을 자동 처리하던 외부 프로그램은 v2 열 구조에 맞게 수정해야 합니다. 이는 외부 분석 문서의 버전 변경이며 기존 앱의 대국 JSON 패보 형식에는 영향을 주지 않습니다.
